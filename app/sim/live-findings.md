# 公開先テストの記録（2026-11-04）

公開先 https://urafess.denkingon.workers.dev （Cloudflare Workers ＋ Durable Object、ゲームの部屋は北東アジア）で確かめたこと。

## 300人テスト：全項目通過

`sim/live.test.ts`、部屋 test-1104、2ラウンド。主催者の操作はブラウザの主催者画面から。詳細は `live-report-300.md`。

- 入室：300人全員、4.1秒
- 配役：押してから0.1秒で全員が受け取り（鬼90・逃走者210、表示の数とも一致）
- 開始：区切りの時刻が全員一致（0.2秒以内）
- 試合中に30人を突然切断：全員つなぎ直し、役も区切りの時刻も元どおり（戻るまで中央値0.7秒・最長1.1秒）
- 時計の見積もりが保証（往復の半分）を外れた人：0/300
- 他人の役・主催者向けの集計が参加者に届いた回数：0

## 想定外のつなぎ直しの原因：作業用の機械の通信の出口

300人テストでは接続が513本あった（初めの300本＋わざと切った30本で約330本のはず）。原因はアプリでも Cloudflare でもなく、
テストを動かした機械（Claude のクラウドの Firecracker 仮想マシン）の出口が、300本前後の同時接続を保てないことだった。

| 接続元 | 本数 | 時間 | 切れた本数 | 往復 中央値 / 最大 |
| --- | --- | --- | --- | --- |
| 作業用の機械（アプリのしくみ GameClient、`diag.test.ts`） | 300 | 6分 | 105（一斉入室で12、放置中に回線側から93） | 192ms / 5.4秒 |
| 作業用の機械（軽い接続、`ws-compare.mjs`） | 50 | 5分 | 0 | 223ms / 486ms |
| 作業用の機械（軽い接続） | 200 | 6分 | 0 | 186ms / 605ms |
| 作業用の機械（軽い接続） | 300 | 6分 | 545 | 189ms / 17.8秒 |
| 作業用の機械（軽い接続、行き先の2つのIPに150本ずつ） | 300 | 5分 | 297 | 342ms / 124秒 |
| 日本のブラウザ（Claude アプリ内） | 50 | 5分 | 0 | 22ms / 117ms |
| 日本のブラウザ（Claude アプリ内） | 200 | 6分 | 0 | 37ms / 253ms |
| 日本のブラウザ（Claude アプリ内） | 254 | 約30秒 | 0 | — |

- 切断はすべて閉じコード1006（説明なしの断線）。切れる前に数十秒〜2分、1通も届かない詰まりが出る。途中の機器が黙ってパケットを捨てるときの症状
- アプリのしくみを外した軽い接続でも、行き先のIPを分けても、300本で切れる。200本では切れない
- Durable Object 1つに WebSocket は32,768本までつなげる（[Cloudflare の資料](https://developers.cloudflare.com/durable-objects/api/websockets/)）。送り元のIPごとの上限は資料にない
- アプリはどの切断からも自動で元の状態に戻った（テストは全部通過）

## 残る穴と、これからのテストの決まり

- 同じ日本のIPから256本を超える接続は確かめていない（ブラウザ1つで張れるのは約255本まで）。本番で全員がキャンパスの Wi-Fi（同じIP）につなぐ場合に関わるので、SFCでの試遊（計画書の段階4）で、同じ Wi-Fi に大人数をつないで確かめる
- この作業用の機械からのボット試験は200本以下にする。それより多いと出口の都合で切れて、結果が濁る
