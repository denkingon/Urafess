# Urafess アプリの土台

入室・①配役（鬼3：逃走者7が初期値。主催者画面の「鬼と逃走者の割合」で変えられる）・②同期タイマー・③捕獲の記録を、300人で崩れないように作ったもの。

- 計画書（正本）：[Urafess アプリ根幹 計画書](https://claude.ai/artifact/7ouAiRxriSSYHpYCdgGRm5)
- 画面の下書き：[Urafess アプリ画面（Claude Design）](https://claude.ai/artifact/9RCkDqT7CL9dtifftVs1SY)

1ラウンドは「配役 → 逃走開始まで20秒 → 追跡開始まで1分 → ゲーム5分 → 広場に戻る2分 → 結果発表」。
主催者が「開始」を押すと、サーバーが区切りの時刻をすべて決めて全員に送り、各スマホはその時刻が来たら自分で次の段階に切り替わる。

## 構成

| 場所 | 中身 |
| --- | --- |
| `src/shared/` | 決まりごと（`rules.ts`）、配役の計算（`allocate.ts`）、区切りの計算（`schedule.ts`）、時計合わせ（`clock.ts`）、捕獲の候補の決め方（`capture.ts`）、画面に渡す中身（`viewmodel.ts`） |
| `src/server/` | Cloudflare Worker と Durable Object（1ゲーム＝1つ、SQLite に保存してから配る）。記録の CSV（`log.ts`） |
| `src/client/core/` | しくみ：接続・つなぎ直し・時計合わせ・状態（見た目を知らない） |
| `src/client/sound/` | 音：3桁を音にする・聞き取る（`codec.ts`、中身は [ggwave](https://github.com/ggerganov/ggwave)・MIT）、鳴らす（`emitter.ts`）、マイク（`listener.ts`） |
| `src/client/views/` と `styles.css` | 見た目。参加者の画面は `phone.ts`＋`player.css`（ルールのアニメと同じ枠）、捕獲は `capture.ts`、音の試しは `lab.ts`、主催者は `host.ts`（まだ仮の白黒） |
| `src/client/ui.ts` | 参加者の画面の決め事（文字の最低ライン・言語・色）と、日本語・英語の言葉の出し方、小さい印 |
| `src/client/picto/engine.js` | 裏フェス ピクトグラムの正本を写したもの（直すときは正本を直してから写す） |
| `src/client/install/` と `views/install.ts` | ホーム画面への置き方の案内（端末の見分け・言葉なしの絵） |
| `icon/` | アイコンの元の SVG（PNG は `src/client/public/` に書き出したもの） |
| `test/` | 単体テスト（配役は1〜300人を全部確かめる。音の読み取り・捕獲の候補も） |
| `sim/` | 300人の機械テスト。結果は `sim/last-report-300.md`。捕獲の機械テストは `sim/capture.test.ts`（結果は `sim/capture-report.md`） |

安定性の芯は3つ。

1. 正解はサーバーの1か所（Durable Object）だけが持つ。操作は1つずつ順番に処理し、保存してから配る
2. つながるたびに「今の全部」を送る。取りこぼしても、次につながった瞬間に正しい状態に戻る
3. タイマーは数えない。区切りの時刻から毎回計算する（裏に回っても、切れても、ずれが溜まらない）

試合中（配役〜タイマー）だけ、さらに2つ足してある。

- **合図**：サーバーが2秒ごとに短い合図（`hb`）を全員に同じ1本で送る。6秒届かなければ、見えない切断とみなしてつなぎ直す（気づくまで最大7秒。以前は30秒ごとの時計合わせ頼みで最大約40秒）。画面に戻ったときに合図が途切れていれば、その場でつなぎ直す。送る側なので無料で、携帯の電波を待機に落とさない（「捕まった」などの知らせが電波の寝起きを待たない）役目もある。合図はアラームで出すので、待合室と結果発表の間は出さず、リクエストも使わない
- **画面を消さない**：Screen Wake Lock。iPhone は画面が消えると接続が切れ、位置も届かなくなるため。裏に回って外れたら、戻ったとき・触れたときに取り直す。ホーム画面のアプリ（iPhone）では iOS 18.4 から使えるので、それより古い人には自動ロックを切ってもらう

## 見た目を差し替えるとき

しくみは `PhoneView`（`src/shared/viewmodel.ts`）だけを画面に渡す。中身はキャンバスの共通部品 Phone の props と同じ：
`round`・`role`（逃走者／鬼／なし）・`step`（0〜6）・`label`・`big`・`message`・`oni`・`runners`・`offline`。
捕獲を入れたときに2つ足した：`touch`（`oni`＝「捕まえた」の長押しを出す／`runner`＝「捕まった」を出す／`none`）と `caught`（自分が捕まった）。`runners` は試合中「残り5/7」の形になる。
新しい見た目は `src/client/views/phone.ts` と `styles.css` を差し替えて、これを描けばいい。主催者画面は `views/host.ts`。
捕獲の画面（長押し・候補・手動）は `views/capture.ts` で、`ClientState`（`me.claim` の候補、`notice` の知らせ、`roster` の一覧）から描く。

### 参加者の画面（アニメと同じ枠）

上＝段階バー（配役・0:20・1:00・5:00・2:00・結果。時間は主催者が決めた長さ）、真ん中＝いまやることのピクト、下＝残り時間（URAJI）と人数の印（鬼は角の頭、逃走者は点。捕まると白抜き。多いときは数字）、ひとこと。
そのために `PhoneView` に足した：`scene`（ピクトの id）・`word`（ひとこと［日本語, 英語］）・`note`（大事なときだけの文）・`time`（大きい数字）・`unit`・`outcome`（自分の側の勝ち負け）・`counts`・`times`・`paused`。

- 値はパレット「裏フェス 画面のパレット」 https://claude.ai/artifact/2uVdsAzPTMrhuJATQKsznX の既定（2026-11-06）。決めた値が来たら `ui.ts` と `player.css` を替える
- **文字の最低ライン**：画面の中の字は全部 `--min`（16px）より小さくしない。URAJI は字の背が低い（字の高さ 0.7em）ので、URAJI の字は 1.2 倍（19.2px）を下限にする
- **言語**：`UI.lang`（日本語＋英語が既定）。短い言葉は `say()`（英語は URAJI の大文字）、文は `sent()`（英語はゴシック）
- 捕獲：鬼の板は朱に角の頭、逃走者の板は月白に両手を上げた人。鬼のマイクは、まだ一度も試していないうちは長押しの板の場所に点線の板で出す（試したあと、止まった・断られたときは小さくして、長押しの板も出す）
- フォントは `public/fonts/URAJI-Black.woff2`（URAJI v0.2）。Service Worker の保存名は `urafess-v3` にした（フォントを保存し直す）

## 捕獲の記録

体で捕まえたあと、鬼は「捕まえた」、逃走者は「捕まった」を**長押し**する（0.5秒押し続けると成立。短く離したら何もしない）。出るのはゲームの段階（とその直後10秒）だけ。

1. 逃走者のスマホは長押しの間、自分のその回の3桁を**超音波**で繰り返し鳴らす。人の耳には、その人だけの**3音のフレーズ**が聞こえる（超音波に重ねたかざり。4kHz より下なので読み取りを邪魔しない）
2. 鬼のスマホは長押しの間マイクで聞く。3桁を拾うと「◯◯（12番）をロックオン」と出て、鬼は離して次を追える
3. 逃走者の画面に「捕まえたのは？」として、候補の鬼が**同じ大きさで並ぶ**。どれを押しても、その鬼が捕まえたとして記録される（押すまで記録しない）。候補になるのは：
   - **音**：逃走者の音を拾った鬼
   - **同時**：逃走者と同じ時間に長押ししていた鬼
   - **鬼が選んだ**：「手動で選ぶ」でこの逃走者を選んだ鬼
   - **前後**：重なっていないが、前後20秒以内に長押しした鬼
4. 記録されると、逃走者に「◯◯に捕まった」、鬼に「◯◯を捕まえた」が届き、全員の「逃走者 残り」が1つ減る

**手動で選ぶ**：逃走者は鬼の一覧から直接選んで記録できる（方式は「手動」）。鬼は捕まっていない逃走者の一覧から選ぶと、その逃走者の候補に「鬼が選んだ」で出る（記録は逃走者が選んだとき）。
**主催者**：「次に進む」で、いまの段階を2秒後に終わらせて次の段階へ進める（全員の画面が同じ瞬間に切り替わる。そのあとの段階の長さは変わらない。ボタンに行き先が出る。ゲームを縮めるときだけ確かめる。一時停止中とあと2秒で終わる段階では押せない）。画面の「捕獲」で、逃走者を押すと手で「捕まった」にする・取り消す。「記録をCSVで保存」で1イベント＝1行の記録（誰が・誰を・何分に・どの方式で、長押し・音を拾った・取り下げなども）を保存する（`/api/game/<ゲームID>/log`、合言葉が要る。`?format=json` で JSON）。部屋を空にしても記録は消えない。

決まりの数字は `src/shared/rules.ts` の「捕獲の記録」にまとめてある（長押しの長さ・前後の幅・答えを待つ長さ・音の送り方と大きさ）。

- 役は本人にしか見せない作りのまま。逃走者に届く候補は「手がかりのある鬼」だけ。ただし**手動の一覧は、逃走者には鬼全員、鬼には捕まっていない逃走者全員が見える**。逃走者が一覧を開けるのは「捕まった」を長押ししたあとだけ、鬼はゲームの段階の間だけ（サーバーもそれ以外は空の一覧を返す）
- 長押し・音・候補は SQLite に保存してから配る。答え待ちのままサーバーが入れ替わっても、つなぎ直した瞬間に候補が戻る。長押しの途中で切れたら、つなぎ直した端末が同じ押し始めを送り直す
- 音：iPhone は「画面に触れた直後」でないと音を出させない。長押しの押し始めはその「直後」に数えられないので、その前のどこかのタップで一度準備する（ゲームの前に逃走者には「音を試す」が出る。鬼には配役からゲームの終わりまで、マイクが本当に音を拾えるようになるまで「マイクをオンにする」を大きく出し続ける。iPhone で画面を離れた・ほかの音のアプリ・電話などでマイクや音の処理が止まったら、また出す）。音は `<audio>` で鳴らすので、消音スイッチが入っていても鳴る。鬼のマイクはゲームの段階が終わるまで開けたままにする（長押しのたびに立ち上がりを待たないため）。音は手元で読むだけで、どこにも送らない
- リクエスト：1回の捕獲で届くのは、長押しの押し始め・離した（2人で4通）＋音を拾った（1通）＋選んだ（1通）くらい。時計合わせに比べて無視できる

### 音の試し（`/lab`）

部屋もサーバーも使わず、2台のスマホで「鳴らす」「聞く」だけを確かめる画面。`https://urafess.denkingon.workers.dev/lab` を2台で開き、片方は「鳴らす」、もう片方は「聞く」を長押しして近づける。拾えた3桁と、押してから何秒で拾えたかが出る。送り方（超音波・聞こえる音）と音量を変えて、いちばん読める組み合わせを `rules.ts` の `SOUND_PROTOCOL`・`SOUND_VOLUME` に入れる。

- 機械の上の試し（`test/sound.test.ts`）では、超音波は話し声・高音の落ち込み・44.1kHz のマイクでも読めた。聞こえる音（audible）は話し声と重なって読み落とした。実機（スピーカーとマイクが 15kHz より上をどこまで出せるか）はまだ確かめていない
- `?debug=1` を付けて開くと、ヘッドレスのブラウザから音の波形を取り出せる（試験用）

## 夜テスト（`/api/probe`）

本番と同じ夜に、何台かのスマホでキャンパスを歩き、位置の精度と更新の間隔・Cloudflare までの往復・実際の回線（AS）・接続の切れ目を記録して1か所に集める画面。
[SFCのWi-Fi調査](https://claude.ai/artifact/UAk9NJn2rn3mq3aEgPhKcF)で推定のまま残った数字を、実測に置き換えるためのもの。

1. `https://urafess.denkingon.workers.dev/api/probe` を開いて「テスト回を作る」。出たリンクを、一緒に歩く全員のスマホで開く
2. 各自、呼び名と今の回線（セルラー／keiomobile2／CNS／eduroam）を選んで「記録を始める」。画面は消さない。回線を変えたら選び直す。目印に立ったら「いま目印に立っている」
3. 「電波の眠りを測る」：通信を止め、1〜20秒の無通信のあとの往復を測る（約2分、その場で待つ）。携帯の電波が何秒で待機に落ちるかが分かる
4. 終わったら「記録を終える」→「このテスト回の結果を見る」。端末ごと・回線ごとの集計が出て、生データは JSON で保存できる

- 画面は Service Worker を通らないよう `/api/` の下に置いてある（アプリ本体の Service Worker は、ページを開くと保存したアプリの画面を返すため）
- 記録はテスト回ごとに1つの Durable Object（`ProbeHub`、SQLite）に入る。テスト回のリンクを知っている人だけが見られ、位置を含むので、終わったら「記録を全部消す」で消せる。IP は上2つ（IPv4）だけ残し、回線は AS（慶應は AS38635）で見分ける
- 接続の切れ目は、アプリ本体と同じく「サーバーが2秒ごとに合図を送り、届かない時間を測る」形で見る（合図が10秒途切れたら張り直して記録する）
- リクエストの目安（10台で2時間）：Worker 約3万（往復3秒ごと・回線1分ごと・送信15秒ごと）、Durable Object 約1.6万（合図のアラーム・送信・WebSocket の往復10秒ごと）。どちらも無料枠（1日10万）に収まるが、本番の日には使わない

## 公開する

Cloudflare（無料プラン）の Worker をこの GitHub リポジトリにつないである。**main に入った変更は自動でビルドされ、そのまま公開される**（Workers Builds）。
ビルドの成否は、GitHub のコミットの横のチェック（Cloudflare の check run）でも見られる。

Cloudflare 側の設定（Worker → Settings → Build）

| 項目 | 値 |
| --- | --- |
| Worker 名 | `urafess` |
| Root directory | `app`（アプリはこのフォルダにある。空だとビルドが失敗する） |
| Build command | `npm run build`（空でも `wrangler deploy` が先にビルドする） |
| Deploy command | `npx wrangler deploy` |
| プレビューコマンド（main 以外のブランチ。設定の「プレビューのベース」側） | `npx wrangler deploy --dry-run`（公開はせず、ビルドと組み立てが通るかだけ確かめる。初期値の `npx wrangler preview` は Durable Object を使うこのアプリでは設定が足りず失敗する） |

主催者用の合言葉は、Worker → Settings → Variables and Secrets に、種類 **Secret**・名前 `HOST_TOKEN` で入れる（作成画面の「Variables」はビルド用なので違う）。
入れるまでは主催者画面が「拒否」になるだけで、参加者側は動く。

手元から直接公開するとき（予備）：

```sh
cd app
npx wrangler login                 # もしくは CLOUDFLARE_API_TOKEN を環境変数に入れる
npx wrangler secret put HOST_TOKEN # 主催者用の合言葉
npm run deploy                     # 画面のビルドも中でやる
```

公開先は `https://urafess.<アカウントのサブドメイン>.workers.dev`。

- 参加者に配るのはトップの URL。LINE の中で開かれたら、アプリが自分で `?openExternalBrowser=1` を付けて外のブラウザへ開き直す（付けて配ってもいい）
- 参加者には前もってホーム画面に追加してもらう（当日の読み込みが通信に頼らなくなる）。新しい版を公開したあとは、試合中でなければ開いたとき（と画面に戻ったとき）に自動で読み込み直して新しい版になる（試合中は次に開いたときに）。iPhone はホーム画面のアプリと Safari で保存場所が別なので、入室は当日ホーム画面のアプリの中で行う
- ゲームの部屋は日本を含む北東アジア（`apac-ne`）に作られる

## ホーム画面に置く

ブラウザで開いた人には、入室の前に置き方の案内が出る。案内の間はサーバーにつながない。

- 押すものを、押す順に、全部を一度に並べる（`src/client/install/steps.ts`）。勝手には進まない
  （前は大きな絵を2秒ごとに1手ずつ映していたが、11/6 の実機で「すんごいわかりにくい」。本物の画面と見比べている間に絵が変わってしまう）
- 押すものは OS の画面の字と絵で書く（「共有」「その他」「ホーム画面に追加」「追加」など。自分の画面で同じ字を探せるように）。字はスマホの言葉（`navigator.language`）に合わせ、日本語でなければ英語の字（Share・More・Add to Home Screen・Add）を出す。数字は URAJI
- 一覧はページの上に置く。OS のメニューやシートは下から出て画面の下半分を隠すが、上の一覧は操作の途中も見えたまま
- 最初に押すボタンは、本物のバーと同じ並びの絵（`scenes.ts` の1枚目の場面の、バーの帯だけ）で場所を見せ、本物のボタンを矢印で指す
- 手ごとに一言（右下の •••・見えなければ上へ送る など）を添え、もう一方の言葉（日本語のスマホなら英語）でも「押すものの字 — 場所」を書く（11/6 本人「B かつ英語も入れて」）。題も2つの言葉で出す
- 出ないこともある手は点線（iPhone の Chrome などで、iOS の版が分からないときの「その他」）

| 開いたところ | 手順 |
| --- | --- |
| iPhone の Safari 26 から | 右下の ••• → 共有 → その他 → 「ホーム画面に追加」 → 右上の「追加」 → ホーム画面のアイコン |
| iPhone の Safari 18 まで | 共有（下の真ん中） → 「ホーム画面に追加」 → 「追加」 → アイコン |
| iPhone の Chrome など | 右上の共有 →（iOS 26 から）その他 → 「ホーム画面に追加」 → 「追加」 → アイコン |
| Android | Chrome がボタン1つで入れられるときは、アイコンと ↓ のボタン1つだけ。出せないときは ⋮ → 「アプリをインストール」 → 「インストール」 → アイコン |
| LINE の中 | 自動で `?openExternalBrowser=1` を付けて外のブラウザへ。それでも LINE の中のままなら、右上のメニュー → 「ブラウザで開く」 |
| Instagram などアプリの中 | 右上のメニュー → 「ブラウザで開く」（開き直した先で、その端末の案内が出る） |

- iOS 26 から、共有シートは最初に4つ（コピーなど）だけ見せ、4つ目が「その他」。「ホーム画面に追加」はその先にある（シートを上へ送っても出る）。ソフトバンクの iOS 26 の手順・MacStories の iOS 26 の記事と同じ
- iPhone の手数（Safari 26 で5手）は Apple の画面の中なので、こちらからは減らせない。案内でできるのは見せ方だけ
- Safari 26 の ••• の位置は、本人が選んだタブの並べ方で変わる（標準のまとまった並べ方なら右下。下・上の並べ方なら共有ボタンが直接出る）。案内は標準の並べ方で描いている
- 出さないとき：ホーム画面のアプリから開いたとき・パソコン・試し部屋（`?g=`）・左上の × を押したあと（そのタブの間）
- Safari 26 は UA の OS の版を 18 台に固定しているので、版は `Version/26` で見る
- 見分け方の単体テストは `test/install-detect.test.ts`、手順の一覧は `test/install-steps.test.ts`

アイコンは新字（うらまつり、URAJI v0.3 の案 C）。字の線をアイコンの下から 0.53 の高さに置いた。

- `icon/icon.svg`：iPhone・ふつうの大きさ用（角は iPhone が丸く切る）
- `icon/icon-maskable.svg`：Android 用。丸く切られても欠けないよう、中心から半径 0.4 の円に収めた
- `icon/alt-runner*.svg`：見比べた案（逃走者のピクト）
- PNG の書き出し：`rsvg-convert -w 512 -h 512 icon/icon.svg | convert - -alpha off PNG24:src/client/public/icon-512.png`（192・180・maskable も同じ）
- すでにホーム画面に置いた人のアイコンは替わらない（置いたときの絵のまま）。替えたいときは一度消して置き直してもらう

## 本番の部屋とリハーサル

- ホーム画面に追加したアプリは、いつも部屋 `main` を開く（`manifest.webmanifest` の `start_url` が `/`）。本番も実機テストも `main` で行うのが、本番と同じ流れになる
- 実機テストやリハーサルのあとは、主催者画面の「部屋を空にする（全員を外す）」で `main` を空にする。参加者は全員外れ、スマホは入室画面に戻る。試合中は押せない
- `?g=名前` の部屋は、ブラウザだけで試すとき用（ホーム画面のアプリからは入れない）

## 本番の日

やらないこと

- main にマージ・push しない（＝自動で公開される）。手元からの `npm run deploy` もしない。公開するとサーバーが入れ替わり、全員の接続が一度切れる（つなぎ直せば元に戻るが、わざわざ起こさない）。前日のうちに Cloudflare 側で自動ビルドを止めておくと安心
- 試合中にゲーム名（`?g=`）を変えない

やること

- 昼のうちに、公開済みのアプリで1ラウンド通し、終わったら「部屋を空にする」
- 開始の前に、主催者画面の「役の受け取り」が全員分そろい、「時計が合っている」がほぼ全員になったのを見る
- Cloudflare 自体が止まったときのために、ストップウォッチと口頭の配役で回す手順を紙で持っておく

## 無料枠

Durable Objects の無料プランは1日10万リクエストで、超えるとその日はエラーになる。戻るのは UTC の0時＝日本時間の朝9時なので、昼のリハーサルと夜の本番は同じ枠を使う
（[料金](https://developers.cloudflare.com/durable-objects/platform/pricing/)）。

- スマホから届く WebSocket のメッセージを20通で1リクエストと数える換算は、料金表では有料プランの欄にだけ注記された「課金のための」換算で、**無料プランの上限にも効くかは書かれていない**（2026-11-04 に確認）。サーバーから送る側は無料
- 今届くのは時計合わせだけ（1人あたり30秒ごとに問い合わせ3通＋報告1通）。300人なら毎秒約40通、2時間で約29万通になる。換算が効けば約1.4万リクエストで余裕だが、効かなければ約40分で尽きる
- 試合中の合図（アラーム）は2秒ごとに1リクエスト（1時間に1,800）
- **本番の月だけ有料プラン（最低月5ドル、月100万リクエスト込み）にすれば、どちらの場合でも尽きない**。位置を毎秒送る形にするなら有料プランが前提
