# Urafess アプリの土台

入室（名簿）・①配役（鬼3：逃走者7が初期値。主催者画面の「鬼と逃走者の割合」で変えられる。参加者は配役の前に、逃走者／鬼の希望を選べる）・②同期タイマー・③捕獲の記録・④走ると光るを、300人で崩れないように作ったもの。

- 計画書（正本）：[Urafess アプリ根幹 計画書](https://claude.ai/artifact/7ouAiRxriSSYHpYCdgGRm5)
- 画面の下書き：[Urafess アプリ画面（Claude Design）](https://claude.ai/artifact/9RCkDqT7CL9dtifftVs1SY)

1ラウンドは「配役 → 逃走開始まで20秒 → 追跡開始まで1分 → ゲーム5分 → 広場に戻る2分 → 結果発表」。
主催者が「開始」を押すと、サーバーが区切りの時刻をすべて決めて全員に送り、各スマホはその時刻が来たら自分で次の段階に切り替わる。

## 配役の希望（逃走者になりたいか、鬼になりたいか）

配役の前に、参加者が自分で「逃走者がいい」「鬼がいい」を選べる。選ばなければ「どちらでも」。

- **選ぶ場所**：次の配役の前だけ。待合室と結果発表（時間が0になったら）の画面の下に、板が2枚並ぶ。途中で来て見学している人には、ゲームが終わってから（広場に戻る間・結果発表）出る（左＝逃走者・月白、右＝鬼・朱と角）。押すと選ぶ、もう一度押すと取り消す。役が決まってからゲームの終わりまでは変えられない
- **板の数字**：`希望している人数／枠`。枠は、いまの入室人数と主催者の割合から出る（10人・鬼3：逃走者7なら 鬼3・逃走者7）。誰が何を希望したかは、ほかの人には見えない（人数だけ）
- **人数は割合のまま変えない**。希望が枠に収まっていれば全員が希望どおりで、残りの枠は「どちらでも」の人が埋める。希望が枠より多い役は、その中からくじで枠の人数だけ通り、外れた人はもう一方の役になる
- **外れた人は、次の配役で優先される**（希望した役の枠に先に入る）。続けて外れた回数が多い人ほど先で、同じ回数どうしはくじ。通ったら 0 に戻る。全員が同じ役を希望し続けても、枠が外れた人数以上あれば、2回続けて外れる人は出ない
- 外れた人の配役の画面には「希望が多かった。次は優先」と出る。次に板が出たとき、希望が枠より多ければ、ひとことが「前に外れたので、今回は優先」になる
- 希望は今夜のあいだ残る（毎回選び直さなくていい）。つなぎ直しても残る。「新しい夜を始める」で消える
- **引き直し**は、引き直す前の回数からやり直す（遊んでいない配役で外れた分を数えない）
- **主催者画面の「配役の決め方」**：「希望を聞く」（初期値）と「くじだけ」（希望の板を出さない。前の版と同じ）を切り替える。待合室・配役済み・結果発表のときだけ変えられ、次の配役から効く。その下に、いまの希望の人数と「このまま配役すると何人がもう一方の役になるか」、配役のあとは「通らなかった人」の数が出る
- **記録（CSV）**：希望を聞いた配役では、「役」の行の詳細に `wish`（その人の希望）・`missed`（通らなかったか）・`prio`（配役の前の、続けて外れた回数）、「配役」の行に `how`（決め方）と `wish`（希望の人数と通らなかった人数）が残る。切り替えは「配役の決め方」の行
- 気をつけること：希望が枠より多い役をわざと希望して外れると、もう一方の役になったうえで、次の配役で優先される。いまは止めていない
- 計算は `src/shared/allocate.ts` の `assignWithWishes`、決まりの説明は `src/shared/rules.ts` の「配役の希望」

## 名簿と今夜（一度登録したら次も使える）

入室したニックネームは「名簿」に残り、次の夜からは名前を押すだけで入れる。番号は画面に出さない（名前で人を見分ける）。

| | 何が入っているか | いつ消えるか |
| --- | --- | --- |
| 名簿 | ニックネーム・合い鍵・名簿に入った順（画面には出さない）・来た夜の数 | 消えない（「新しい夜を始める」でも残る） |
| 今夜 | 今夜の参加・役・捕獲 | 主催者が「新しい夜を始める」（前の「部屋を空にする」）を押したとき |

- スマホには合い鍵（`urafess:main:me`）だけが残る。開くと合い鍵で戻り、今夜に入っていればそのまま、名簿にだけいれば名前の大きなボタンが出る。押すと今夜に入る。開いただけでは入らない（配役はつながっていない人も含めて引くので、家で開いた人まで役が付かないように）
- 名前は名簿の中で1人1つ。全角半角・カタカナとひらがな・大文字小文字・空白や中黒の違いは同じ名前とみなす（`src/shared/names.ts`）
- 合い鍵のないスマホ（アイコンを置き直した・Safari で入った・機種を変えた）で名簿にある名前を入れると「前に来た人の名前」と出る。「前の自分に戻る」を押すと主催者画面の「戻りたい人」に出て、主催者が「つなぐ」を押すと前の自分の合い鍵を受け取る（同じ名前の別人と取り違えないため、つなぐのは主催者）。「断る」と名前の入力に戻る
- 「別の人として入る」（名前のボタンの下）：このスマホが覚えている人を忘れて、名前の入力に戻る。名簿からは消えない
- 名簿に入ったスマホは、保存場所を消さないでほしいと頼む（`navigator.storage.persist()`。iPhone はホーム画面のアプリから開いたときに通りやすい）
- 名簿を入れる前の版で入った参加者（外されていない人）は、入れ替えた最初の1回だけ、pid・合い鍵・番号のまま名簿へ移る。その人のスマホは入り直さなくていい（`sim/migrate.test.ts`）
- 記録（CSV）には、新しく入った `join`・名前のボタンで入った `enter`・名前が名簿にあった `taken`・戻りたい `reclaim-ask`・つないだ `reclaim-ok`・断った `reclaim-no` が残る。pid は夜をまたいで同じなので、同じ人の夜ごとの記録をつなげて見られる
- 名簿は今の部屋の Durable Object に置くので、リクエストは増えない

### 自分のページ

名前のボタンの画面と、試合の外（待合室・結果・夜を終えたあと）の参加者の画面の「自分のページ」から開く。`/api/game/<ゲームID>/me`（合い鍵は `x-pid`・`x-key` の見出し。写真と同じ）。

- 記録：来た夜（日本時間の朝6時で区切る。部屋で遊んだ夜を並べ、来た夜を塗る）・鬼／逃走者だった回数（始まったラウンドだけ。配り直す前の役は数えない）・捕まえた・捕まった（主催者が取り消した捕獲は数えない）・牢屋から助けた。数え方は `src/shared/account.ts` の `summarizeAccount`
- 名前を変える：名簿で1人1つのまま。試合中（配役〜タイマー）で今夜に入っている人は変えられない。開いているスマホにも新しい名前が届き、古い名前は空く。記録に `rename`
- 新しいスマホへ移す：古いスマホに6桁の合言葉（10分・1回だけ）。新しいスマホの入室画面の「前のスマホから移す」で打つと、合い鍵を作り直して新しいスマホに渡し、古いスマホは入室画面に戻る（主催者につないでもらわなくていい）。打ち間違いは部屋全体で10分に20回まで（当てずっぽう止め）。記録に `handoff`
- このスマホから出る：「別の人として入る」と同じ（このスマホが名前を忘れる。名簿と記録は残る）
- 名簿から消える：名簿と今夜から外れ、名前が空く。記録の名前は「消えた人」になる（数は残る）。試合中で今夜に入っている人はできない。記録に `leave`
- 確かめ：`test/account.test.ts`（数え方）・`sim/account.test.ts`（手元のサーバーで、名前を変える・移す・消える・合言葉の止まり方）

安定性の芯は3つ。

1. 正解はサーバーの1か所（Durable Object）だけが持つ。操作は1つずつ順番に処理し、保存してから配る
2. つながるたびに「今の全部」を送る。取りこぼしても、次につながった瞬間に正しい状態に戻る
3. タイマーは数えない。区切りの時刻から毎回計算する（裏に回っても、切れても、ずれが溜まらない）

試合中（配役〜タイマー）だけ、さらに2つ足してある。

- **合図**：サーバーが2秒ごとに短い合図（`hb`）を全員に同じ1本で送る。6秒届かなければ、見えない切断とみなしてつなぎ直す（気づくまで最大7秒。以前は30秒ごとの時計合わせ頼みで最大約40秒）。画面に戻ったときに合図が途切れていれば、その場でつなぎ直す。送る側なので無料で、携帯の電波を待機に落とさない（「捕まった」などの知らせが電波の寝起きを待たない）役目もある。合図はアラームで出すので、待合室と結果発表の間は出さず、リクエストも使わない
- **画面を消さない**：Screen Wake Lock。iPhone は画面が消えると接続が切れ、位置も届かなくなるため。裏に回って外れたら、戻ったとき・触れたときに取り直す。ホーム画面のアプリ（iPhone）では iOS 18.4 から使えるので、それより古い人には自動ロックを切ってもらう

## 見た目を差し替えるとき

しくみは `PhoneView`（`src/shared/viewmodel.ts`）だけを画面に渡す。中身はキャンバスの共通部品 Phone の props と同じ：
`round`・`role`（逃走者／鬼／なし）・`step`（0〜6）・`label`・`big`・`message`・`oni`・`runners`・`offline`。
捕獲を入れたときに2つ足した：`touch`（`oni`＝「捕まえた」の長押しを出す／`runner`＝「捕まった」を出す／`none`）と `caught`（自分が捕まった）。`runners` は試合中「残り5/7」の形になる。
走ると光るで2つ足した：`glow`（`prep`＝配役〜追跡開始まで。センサーの準備／`live`＝ゲームの段階。光の地図を出す／`none`）と `lightable`（いま走ったら光る）。地図は Phone の時計と長押しの間（`stage`）に入り、`live` の間は上を詰めて地図に高さを譲る。
新しい見た目は `src/client/views/phone.ts` と `styles.css` を差し替えて、これを描けばいい。主催者画面は `views/host.ts`。
捕獲の画面（長押し・候補・手動）は `views/capture.ts` で、`ClientState`（`me.claim` の候補、`notice` の知らせ、`roster` の一覧）から描く。

### 本部（新しい主催者画面）

主催者画面には、前の画面（`views/host.ts`）と本部（`views/hq.ts`・`hq.css`）の2つがある。前の画面は消していない。
前の画面のいちばん上の「新しい本部 HQ を試す」で本部になり、本部の「デッキ」のいちばん下の「前の主催者画面に戻る」で戻る（端末ごとに覚える。`/host?hq=1` でも本部になる）。

本部は、前の画面のしくみ（`createHost`）をそのまま使い、中の部品を4つの場所へ並べ替えて、その上に並びを足しているだけ。押したときに起きること・確かめの文・サーバーとのやりとりは前の画面と同じ。

- 上から：段階の帯（参加者の段階バーと同じ名前）→ いま（時間・人数）→ 要対応（いちばん上の1件を選択肢つきで）→ 4つの場所 → 押すもの → タブ
- 4つの場所：地図（全体の地図・遊ぶ範囲）／人（戻りたい人・役の名前・捕獲と牢屋）／ミッション／デッキ（時間と割合の＋−・配役の決め方・鬼のマイク・固定の札・そろい具合・夜とやり直し・記録）。前の画面にあとから足された部品でここがまだ知らないものは、デッキの下の「そのほか」に集まる
- 月白の板（塗り）は「返事を待っている」ものだけ：配役・開始・再開・次のラウンド・夜の終わりの「記録を保存」と、要対応の「つなぐ」
- 幅 1024px より広い画面は3列（試合中は 人｜地図｜ミッション・デッキ、それ以外は デッキ｜地図｜人・ミッション）
- 時間の＋−の刻みは 5秒・10秒・1分・30秒（`hq.ts` の `TIME_STEP`）。押すたびに、前の画面の「時間を変える」と同じ命令を送る
- まだ無いもの：要対応を全部並べる一覧、切れている人が誰か、いま起きたことの流れ、長押しで実行（いまは確かめの箱のまま）、デッキを名前をつけて残す、固定の札を本部から変える

絵はキャンバス「Urafess 本部（管理者画面）」。

### 参加者の画面（アニメと同じ枠）

上＝段階バー（配役・0:20・1:00・5:00・2:00・結果。時間は主催者が決めた長さ）、真ん中＝いまやることのピクト、下＝残り時間（URAJI）と人数の印（鬼は角の頭、逃走者は点。捕まると白抜き。多いときは数字）、ひとこと。
そのために `PhoneView` に足した：`scene`（ピクトの id）・`word`（ひとこと［日本語, 英語］）・`note`（大事なときだけの文）・`time`（大きい数字）・`unit`・`outcome`（自分の側の勝ち負け）・`counts`・`times`・`paused`。

- 値はパレット「裏フェス 画面のパレット」 https://claude.ai/artifact/2uVdsAzPTMrhuJATQKsznX の既定（2026-11-06）。決めた値が来たら `ui.ts` と `player.css` を替える
- **文字の最低ライン**：画面の中の字は全部 `--min`（16px）より小さくしない。URAJI は字の背が低い（字の高さ 0.7em）ので、URAJI の字は 1.2 倍（19.2px）を下限にする
- **言語**：`UI.lang`（日本語＋英語が既定）。短い言葉は `say()`（英語は URAJI の大文字）、文は `sent()`（英語はゴシック）
- 捕獲：鬼の板は朱に角の頭、逃走者の板は月白に両手を上げた人。鬼のマイクは、まだ一度も試していないうちは長押しの板の場所に点線の板で出す（試したあと、止まった・断られたときは小さくして、長押しの板も出す）
- フォントは `public/fonts/URAJI-Black.woff2`（URAJI v0.4。英小文字・祭・新字入り。英大文字・数字・カナ・裏は v0.2 と同じ形と字幅）。Service Worker の保存名は `urafess-v3`（v0.2 のときに保存し直した）。フォントを差し替えても保存名は変えない：開いたときに裏で取り直し、次に開いたときから新しいフォントになる
- URAJI で出している英語は、ソースで大文字に書く（小文字で書くと小文字が出る。入る画面の題「Urafess」だけは小文字を含む）

## 捕獲の記録

体で捕まえたあと、逃走者は「捕まった」を**長押し**する（0.5秒押し続けると成立。短く離したら何もしない）。**0.5秒押したら離してよく**、押し始めから3秒までは押しているのと同じに続く（音も鳴り続ける。その間にまた押せば、同じ長押しのまま続く）。鬼は押さなくてもいい（押せば「同時」の手がかりになる）。出るのはゲームの段階（とその直後10秒）だけ。

1. 逃走者のスマホは長押しの間、自分のその回の3桁を**超音波**で繰り返し鳴らす。人の耳には、その人だけの**3音のフレーズ**が聞こえる（超音波に重ねたかざり。4kHz より下なので読み取りを邪魔しない）
2. 鬼のスマホの聞き方は、主催者画面の「鬼のマイク」で切り替える（いつでも。試合中に変えても、そのときから全員に効く。どちらのときの記録かは CSV の詳細に `mic` で残る）：
   - **ずっと聞く**（既定）：マイクをオンにしたら、ゲームの段階の間ずっと聞いている（押さなくていい。板に波が薄く出る）
   - **押している間だけ**：「捕まえた」を押している間だけ聞く（前の版と同じ）
   3桁を拾うと「◯◯をロックオン」と出る
3. **鬼がちょうど1人に決まれば、逃走者は選ばない**：逃走者が離した時点で、その長押しの間に音を拾った鬼か、同時に長押ししていた鬼が合わせて1人だけなら、その鬼で記録する。0人か2人以上なら、逃走者の画面に「捕まえたのは？」として、候補の鬼が**同じ大きさで並ぶ**（押している間と離した直後1.5秒は出さない）。どれを押しても、その鬼が捕まえたとして記録される。候補になるのは：
   - **音**：逃走者の音を拾った鬼
   - **同時**：逃走者と同じ時間に長押ししていた鬼
   - **鬼が選んだ**：「手動で選ぶ」でこの逃走者を選んだ鬼
   - **前後**：重なっていないが、前後20秒以内に長押しした鬼
4. 記録されると、逃走者に「◯◯に捕まった」、鬼に「◯◯を捕まえた」が届き、全員の「逃走者 残り」が1つ減る

**手動で選ぶ**：逃走者は鬼の一覧から直接選んで記録できる（方式は「手動」）。鬼は捕まっていない逃走者の一覧から選ぶと、その逃走者の候補に「鬼が選んだ」で出る（記録は逃走者が選んだとき）。
**主催者**：「次に進む」で、いまの段階を2秒後に終わらせて次の段階へ進める（全員の画面が同じ瞬間に切り替わる。そのあとの段階の長さは変わらない。ボタンに行き先が出る。ゲームを縮めるときだけ確かめる。一時停止中とあと2秒で終わる段階では押せない）。画面の「捕獲」で、逃走者を押すと手で「捕まった」にする・取り消す。「記録をCSVで保存」で1イベント＝1行の記録（誰が・誰を・何分に・どの方式で、長押し・音を拾った・取り下げなども）を保存する（`/api/game/<ゲームID>/log`、合言葉が要る。`?format=json` で JSON）。新しい夜を始めても（部屋を空にしても）記録は消えない。

決まりの数字は `src/shared/rules.ts` の「捕獲の記録」にまとめてある（長押しの長さ・前後の幅・答えを待つ長さ・音の送り方と大きさ）。

- 役は本人にしか見せない作りのまま。逃走者に届く候補は「手がかりのある鬼」だけ。ただし**手動の一覧は、逃走者には鬼全員、鬼には捕まっていない逃走者全員が見える**。逃走者が一覧を開けるのは「捕まった」を長押ししたあとだけ、鬼はゲームの段階の間だけ（サーバーもそれ以外は空の一覧を返す）
- 長押し・音・候補は SQLite に保存してから配る。答え待ちのままサーバーが入れ替わっても、つなぎ直した瞬間に候補が戻る。長押しの途中で切れたら、つなぎ直した端末が同じ押し始めを送り直す
- 選ばずに記録するのは、離した瞬間が分かるときだけ（切れて離した瞬間が分からない長押しでは決めない）。離した直後に遅れて届いた音の知らせ（2秒まで）も、その長押しの音として数える。記録には `auto` の印がつく
- 押さずに聞いている鬼が、そばにいただけで音を拾うことはある。そのときも、拾った鬼が2人以上なら選ぶ画面になる。ほんとうに捕まえた鬼のスマホが拾えず、そばの1人だけが拾ったときは、その鬼の記録になる（人数は合う。誰が捕まえたかは主催者が直せる）
- 電池：マイクは配役のあとから開けたままなので、ずっと聞くために増えるのは読み取りの計算だけ（手元の計測で1コアの0.1〜6%）。実機での減り方はまだ測っていない
- 音：iPhone は「画面に触れた直後」でないと音を出させない。長押しの押し始めはその「直後」に数えられないので、その前のどこかのタップで一度準備する（ゲームの前に逃走者には「音を試す」が出る。鬼には配役からゲームの終わりまで、マイクが本当に音を拾えるようになるまで「マイクをオンにする」を大きく出し続ける。iPhone で画面を離れた・ほかの音のアプリ・電話などでマイクや音の処理が止まったら、また出す）。音は `<audio>` で鳴らすので、消音スイッチが入っていても鳴る。鬼のマイクはゲームの段階が終わるまで開けたままにする（長押しのたびに立ち上がりを待たないため）。音は手元で読むだけで、どこにも送らない
- リクエスト：1回の捕獲で届くのは、長押しの押し始め・離した（2〜4通）＋音を拾った（1通）＋選んだ（0〜1通）くらい。時計合わせに比べて無視できる

### 音の試し（`/lab`）

部屋もサーバーも使わず、2台のスマホで「鳴らす」「聞く」だけを確かめる画面。`https://urafess.denkingon.workers.dev/lab` を2台で開き、片方は「鳴らす」、もう片方は「聞く」を長押しして近づける。拾えた3桁と、押してから何秒で拾えたかが出る。送り方（超音波・聞こえる音）と音量を変えて、いちばん読める組み合わせを `rules.ts` の `SOUND_PROTOCOL`・`SOUND_VOLUME` に入れる。

- 機械の上の試し（`test/sound.test.ts`）では、超音波は話し声・高音の落ち込み・44.1kHz のマイクでも読めた。聞こえる音（audible）は話し声と重なって読み落とした。実機（スピーカーとマイクが 15kHz より上をどこまで出せるか）はまだ確かめていない
- `?debug=1` を付けて開くと、ヘッドレスのブラウザから音の波形を取り出せる（試験用）

## 牢屋と解放・終わり方

捕まった逃走者は、決めた牢屋（当日決める場所）へ歩いて行って待つ。画面は「牢屋」になり、何回でも出入りできる。決まりの数字は `src/shared/rules.ts` の「牢屋と解放」、終わり方の決め方は `src/shared/jail.ts`（サーバーとスマホが同じものを使う）。画面は `views/jail.ts`。

**出る道は2つ**

1. **仲間が牢屋に来て触れる**
   - 牢屋の人のスマホは、牢屋に入ったときからマイクで聞いている（オンになるまで「マイクをオンにする」を出し続ける）
   - 外の逃走者には、牢屋に仲間がいる間だけ「助ける」の長押しが出る。押している間、その人の**助ける番号**（捕まったときの番号とは別の3桁）を**最大音量**の超音波で鳴らす
   - 牢屋の人のスマホがそれを拾った瞬間に、その場で出る（選ぶ画面は無い）
   - 音が届かないときの予備：牢屋の人が「助けて」、助ける人が「助ける」を**同時に長押し**すると、重なった瞬間に出る
   - 1回の長押しで出せるのは1人（そばに牢屋の人が何人いても、最初に拾った1人）。出したあと3秒（`RESCUE_GAP_MS`）は次を出せない
   - 鬼のマイクが助ける番号を拾っても、捕獲の手がかりにはならない
2. **仲間がミッションをクリアする**：主催者画面の「ミッション成功」で、牢屋の全員・1人・人数を決めて、を選んで出す（牢屋に入ったのが古い順）。ミッションの中身はアプリの外で決める

出た人は10秒（`RESCUE_IMMUNE_MS`）捕まらない（「捕まった」が出ない。鬼が手動で選んでも断る）。出られるのはゲームの段階が動いている間だけ。

**終わり方**

- 逃走者が**全員同時に**牢屋に入ったら、その2秒後に全員の画面でゲームの段階が終わる（「次に進む」と同じく、全員が同じ瞬間に切り替わる）。広場に戻る時間はそのまま。その配役は鬼の勝ちで決まり、もう誰も出られない
- 時間切れのとき1人でも牢屋の外にいれば、逃走者の勝ち
- 結果は時間が0になったときにアプリが出す（サーバーが合図のついでに決める。スマホも同じ決め方で、待たずに出す）。主催者の「鬼の勝ち」「逃走者の勝ち」は、直したいときだけ押す
- 終わり際の捕獲が遅れて記録されて、全員が牢屋にいたことになったら、アプリが結果を決め直す（主催者が直したあとは決め直さない）

記録（CSV）には、`rescue`（誰が誰を・音／同時／ミッション／主催者・牢屋にいた時間）、`rescue-hold`、`mission-free`（ミッション成功で出した）、`immune`、`all-caught`、`result`（`auto` の印つき）が残る。鬼の「捕まえた数」は、出られても減らない（主催者の取り消しでだけ減る）。

## ミッションの種類（集合写真・合流・範囲）

主催者画面（本部は「ミッション」のタブ）で、種類を選んで出す。題・締め切り・「成功で牢屋から出す人数」はどの種類も同じ場所で決め、種類ごとの決めごとだけ下に出る。ミッションは1つずつ（次を出すと前のは締め切る）。配役し直す・新しい夜を始めると消える。

| 種類 | 出せるとき | 成功の決まり | だれに見えるか |
| --- | --- | --- | --- |
| 集合写真 | 夜の最後以外 | 写真を送り、主催者が見て「成功」を押す | 成功した人の名前は全員。写真は時間が0になってから |
| 合流 | 配役のあと〜ゲームの段階の終わり | 指定された逃走者どうしが、2人で同時に長押し（牢屋の「助ける」と同じ押し方）。重なった瞬間に成功 | 組は鬼にも見える（組が6以下なら名前、多ければ組の数） |
| 範囲 | ゲームの段階（追跡が始まってから）の間 | 締め切りの瞬間に、主催者が地図に描いた範囲の中の逃走者（牢屋の外）が決めた人数以上 | 範囲（全体の地図の蓄光の枠）・残り時間・いま中にいる人数は、鬼にも見える |

- **合流の組**：「全員を2人組に」＝捕まっていない逃走者を無作為に2人組（奇数なら最後の組だけ3人で、そのうち2人が合えば成功）。1組が成功するたびに、決めておいた人数を牢屋から出す。全部の組が成功したら締め切る。「1組だけ」＝無作為の2人。誰と誰かが全員に出る（ほかの逃走者は助け、鬼は止める）
- 相手が牢屋にいる間は合流できない（先に助ける）。牢屋の人は範囲の人数に数えない
- **範囲の判定**：位置は全体の地図と同じもの（5秒ごと・誤差80m以下）。線から5m外までは中に数える。判定はサーバーがする（遅れても合図の間隔＝2秒まで）。締め切りの前にゲームの段階が終わったら、その場で判定する。やり直し（配役に戻す）では判定しないで締め切る
- 試合を止めている間は、締め切りも止まる（再開で、止めていた分だけ後ろへずれる）
- 範囲の形は、出す前に描いておける（主催者のスマホが覚えている）。出せるのはゲームの段階の間だけ（位置が届くのがその間だけ）
- 記録（CSV）：`mission`（種類・組・範囲・人数）、`meet-hold`、`meet`（誰と誰が合流したか）、`mission-zone`（判定：中にいた人の名前・人数）、`mission-free`（どのミッションの成功で出したか）、`mission-close`（結果）
- 手元のサーバーでの通し：`npx vitest run --config vitest.sim.config.ts sim/mission-kinds.test.ts`

## 走ると光る

走っている人は、**全員の画面に名前と場所が光る**。止まると消える。光るのはゲームの段階（追跡が始まってから終わるまで）が動いている間だけ（逃げて散る間に光ると、隠れた場所が全部ばれるため。一時停止中も光らない）。捕まった人・見学の人は光らないが、光った人は見える。主催者の画面にも出る。

1. 配役のあと、参加者の画面に「**走ると光るをオンにする**」が出る。押すと動きのセンサーと位置の許可を聞く（iPhone は押さないと動きのセンサーを使えない）。一度押せば、その画面を開いている間は次のラウンドも自動でつく
2. **走っているかはスマホが自分で決める**：重力込みの加速度の大きさで、1歩ごとの強い揺れ（16 m/s² を超えて 11 を下回るまで）を数え、2.5秒の間に4歩以上・テンポ 2.2歩/秒以上・最後の1歩が今に近ければ「走り」。0.6秒続いたら光り、走りでなくなって2秒で消える（角を曲がる一瞬では消えない）。動きのセンサーが使えないスマホは、スマホが出す速さ（時速10km 以上が2回続く）で決める（位置の差からは出さない。止まっていても位置は 10m くらい飛ぶので、隠れている人が光ってしまう）
3. 光っている間だけ、1秒ごとに位置をサーバーへ送る（これとは別に、下の「全体の地図」のために全員が5秒ごとに位置を送る）
4. サーバーは光っている人の番号・名前・位置（小数5桁＝約1m）・誤差だけを、全員に同じ1本で配る（光った・消えたはすぐ、位置の更新は 250ms ごとにまとめて）。**役は入れない**（走っているのが鬼か逃走者かは、動きを見て決める）。位置が5秒届かなければ消す
5. 画面：**光の地図**（自分が真ん中。輪は 50m・100m・200m、縁が 400m。近いほど広く描く）と、いちばん近い人の行（名前・方角・距離・ほか何人）。方角が取れれば自分の向いている方が上、取れなければ北が上（一覧に「北東 80m」）。光った人の少し前までの道すじが尾になる。新しく光った人がいると震える（Android だけ。自分が走っている間は震えない）。自分が光っている間は、役の札の横に「**光っている**」（全員に届いたら「…」が取れる）
6. 記録：光った（走り出した）・消えた（止まった／位置が届かなくなった／ゲームの段階の外／捕まった／配役から外れた）を1行ずつ。消えた行に、光っていた長さ・走ったおおよその距離・2秒ごとの道すじが入る

決まりの数字は `src/shared/rules.ts` の「走ると光る」にまとめてある。主催者の画面の「走ると光る」には、今の配役でつながっている人のうち、動きのセンサー・位置が使える人の数が出る（足りなければ、その人に「オンにする」を押してもらう）。

- リクエスト：光っている1人につき1秒に1通。50人のうち平均5人が光っているなら、5分のゲームで約1,500
- iPhone の画面を消す（ロックする）と、動きも位置も止まる＝光らない。試合中は画面を消さない作りだが、手で消すことはできる（決まりで止める）

## 全体の地図（仲間の居場所）

ゲームの段階の地図は、**全体の地図**（北が上の SFC）と**光の地図**（近く：自分が真ん中）を上のボタンで切りかえる。最初は全体の地図。

- ゲームの段階（追跡が始まってから終わるまで）の間だけ、配役に入っている全員のスマホが **5秒ごと** に位置を送る（`pos`。誤差 80m 以下・5分以内の位置だけ。止まっているスマホは位置を出し直さないことがあるので、少し古くても送る）
- **見えるのは役ごと**：鬼には鬼どうし、逃走者には（捕まっていない）逃走者どうし、主催者には全員（役つき）。見学の人には誰も見えない。相手の役の位置は配らない。相手が見えるのは、走って光ったときだけ（役の分からない白い光）
- 捕まった逃走者は送らない・地図から消える（本人には仲間がまだ見える）。16秒届かなければ消える。段階が終わると全員消える
- サーバーは届いた位置をまとめて **1秒に1回** 配る（人が増えた・消えたはすぐ）。位置は記録（CSV）に残さない（1晩で数万行になり、保存の無料枠を食う）
- 地図：最初の枠は SFC のキャンパス（`CAMPUS_BOX`）。人がその外にいればそこまで広げる（キャンパスから 2km より遠い人は数えない）。下地は OpenStreetMap の地図を暗くしたもの（画像はブラウザが直接読む。サーバーのリクエストは使わない。読めなくても点は出る）。鬼は朱に2本の角、逃走者は月白、自分は蓄光の輪と誤差の円、光っている人は光の輪。名前は重ならない分だけ（16px）
- 位置の許可は「走ると光るをオンにする」で一緒に聞く
- 決まりの数字は `src/shared/rules.ts` の「全体の地図」。機械テストは `sim/mates.test.ts`
- Wi-Fi（keiomobile2 など）につないでも位置は正確にも速くもならない（ウェブのページは Wi-Fi を読めない。屋外の誤差は衛星で決まる）。Wi-Fi で得するのはモバイルデータだけ

### 走りの試し（`/lab?k=run`）

部屋もサーバーも使わず、1台で「走ると光る」の判定を確かめる画面。スマホを持って（手・ポケット・かばん）歩く・小走り・全力で走るをやって、「光っている」に切り替わるかを見る。揺れの波形（数えた1歩が白い点）・テンポ・強さ・位置の速さ・方角が出る。テンポと強さの下限はつまみで変えられるので、いちばん合う値を `rules.ts` の `RUN_CADENCE_MIN`・`RUN_PEAK_MIN` に入れる。

## 夜テスト（`/api/probe`）

本番と同じ夜に、何台かのスマホでキャンパスを歩き、位置の精度と更新の間隔・Cloudflare までの往復・実際の回線（AS）・接続の切れ目を記録して1か所に集める画面。
[SFCのWi-Fi調査](https://claude.ai/artifact/UAk9NJn2rn3mq3aEgPhKcF)で推定のまま残った数字を、実測に置き換えるためのもの。

1. `https://urafess.denkingon.workers.dev/api/probe` を開いて「テスト回を作る」。出たリンクを、一緒に歩く全員のスマホで開く
2. 各自、呼び名と今の回線（セルラー／keiomobile2／CNS／eduroam）を選んで「記録を始める」。画面は消さない。回線を変えたら選び直す。目印に立ったら「いま目印に立っている」
3. 「電波の眠りを測る」：通信を止め、1〜20秒の無通信のあとの往復を測る（約2分、その場で待つ）。携帯の電波が何秒で待機に落ちるかが分かる
4. 終わったら「記録を終える」→「このテスト回の結果を見る」。端末ごと・回線ごとの集計が出て、生データは JSON で保存できる

- 画面は Service Worker を通らないよう `/api/` の下に置いてある（アプリ本体の Service Worker は、ページを開くと保存したアプリの画面を返すため）
- 記録はテスト回ごとに1つの Durable Object（`ProbeHub`、SQLite）に入る。テスト回のリンクを知っている人だけが見られ、位置を含むので、終わったら「記録を全部消す」で消せる。IP は上2つ（IPv4）だけ残し、回線は AS（慶應は AS38635）で見分ける
- 接続の切れ目は、アプリ本体と同じく「サーバーが2秒ごとに合図を送り、届かない時間を測る」形で見る（合図が10秒途切れたら張り直して記録する）
- リクエストの目安（10台で2時間）：Worker 約3万（往復3秒ごと・回線1分ごと・送信15秒ごと）、Durable Object 約1.6万（合図のアラーム・送信・WebSocket の往復10秒ごと）。どちらも無料枠（1日10万）に収まるが、本番の日には使わない

## 公開する

Cloudflare（無料プラン）の Worker をこの GitHub リポジトリにつないである。**main に入った変更は自動でビルドされ、そのまま公開される**（Workers Builds）。
ビルドの成否は、GitHub のコミットの横のチェック（Cloudflare の check run）でも見られる。

Cloudflare 側の設定（Worker → Settings → Build）

| 項目 | 値 |
| --- | --- |
| Worker 名 | `urafess` |
| Root directory | `app`（アプリはこのフォルダにある。空だとビルドが失敗する） |
| Build command | `npm run build`（空でも `wrangler deploy` が先にビルドする） |
| Deploy command | `npx wrangler deploy` |
| プレビューコマンド（main 以外のブランチ。設定の「プレビューのベース」側） | `npx wrangler deploy --dry-run`（公開はせず、ビルドと組み立てが通るかだけ確かめる。初期値の `npx wrangler preview` は Durable Object を使うこのアプリでは設定が足りず失敗する） |

主催者用の合言葉は、Worker → Settings → Variables and Secrets に、種類 **Secret**・名前 `HOST_TOKEN` で入れる（作成画面の「Variables」はビルド用なので違う）。

主催者の入口（合言葉の画面）

- 行き方：ホーム画面のアプリの最初の画面（入室）で、題「URAFESS」を1.5秒長押し。一度主催者で入ったスマホには、次から入室の右上に「主催者 HOST」が出る（参加者のスマホには出ない）。ブラウザなら `/host`。ホーム画面のアプリには URL の欄が無いので、アプリからはこの入口だけ
- 合言葉は見える字で打つ（伏せ字の欄だと、スマホは日本語のキーボードに切り替えられず、日本語の入った合言葉が打てない）
- 空白のあるなし・大文字小文字・全角半角のちがいは同じ合言葉とみなす（`src/shared/hostkey.ts`）。字がちがえば合わない
- 「入る」で `/api/game/<ゲームID>/key` に聞いて、合っているのを確かめてからこの端末に覚えさせる（204＝合っている、403＝違う）。違っても打った字は消えない
- ヘッダー `x-host-token` には合言葉を % の形（`encodeURIComponent`）で載せる。日本語をそのまま載せるとブラウザが送る前にエラーにするので、前は日本語の入った合言葉だと「記録をCSVで保存」と写真が動かなかった
- アプリを保存した直後の、次の1回の読み込みだけ失敗していたのを直した（`public/sw.js`）。保存するページを `/index.html` で取りに行くと、サーバーが `/` へ送り直した返事がそのまま保存され、ブラウザはそれをページの読み込みに返すとエラーにする（Chrome は ERR_FAILED）。1回失敗すると裏で取り直して直るので気づきにくいが、はじめてのスマホで題を長押しして入口へ行くと、ちょうどその1回に当たる。保存するときに作り直し、前の版が残した分も返す前に作り直す
- 合言葉は主催者画面のいちばん下「合言葉を変える」で変えられる（`POST /api/game/<ゲームID>/key`、いまの合言葉で入っている人だけ。204＝変えた、400＝短すぎる・長すぎる、403＝主催者ではない）。決めた合言葉はその部屋の保存場所（meta の `hostkey`）に入り、新しい夜を始めても消えない。Cloudflare の `HOST_TOKEN` は予備の鍵として効き続ける（忘れたときに入れるように。止めたいときは Cloudflare 側を変える）。そろえたあと8文字以上（`HOST_KEY_MIN`）。記録には「主催者の合言葉を変えた」だけが残り、合言葉そのものは残らない。部屋ごとのものなので、`?g=` の試し部屋には効かない
- 合言葉を数字4桁のように短くするなら、当てずっぽうを止めるしくみ（続けて間違えたら待たせる）を先に足す。いまは何回でも試せるので、主催者画面で決める合言葉は8文字より短くできない
入れるまでは主催者画面が「拒否」になるだけで、参加者側は動く。

手元から直接公開するとき（予備）：

```sh
cd app
npx wrangler login                 # もしくは CLOUDFLARE_API_TOKEN を環境変数に入れる
npx wrangler secret put HOST_TOKEN # 主催者用の合言葉
npm run deploy                     # 画面のビルドも中でやる
```

公開先は `https://urafess.<アカウントのサブドメイン>.workers.dev`。

- 参加者に配るのはトップの URL。LINE の中で開かれたら、アプリが自分で `?openExternalBrowser=1` を付けて外のブラウザへ開き直す（付けて配ってもいい）
- 参加者には前もってホーム画面に追加してもらう（当日の読み込みが通信に頼らなくなる）。新しい版を公開したあとは、試合中でなければ開いたとき（と画面に戻ったとき）に自動で読み込み直して新しい版になる（試合中は次に開いたときに）。iPhone はホーム画面のアプリと Safari で保存場所が別なので、入室は当日ホーム画面のアプリの中で行う
- ゲームの部屋は日本を含む北東アジア（`apac-ne`）に作られる

## ホーム画面に置く

ブラウザで開いた人には、入室の前に置き方の案内が出る。案内の間はサーバーにつながない。

- 押すものを、押す順に、全部を一度に並べる（`src/client/install/steps.ts`）。勝手には進まない
  （前は大きな絵を2秒ごとに1手ずつ映していたが、11/6 の実機で「すんごいわかりにくい」。本物の画面と見比べている間に絵が変わってしまう）
- 押すものは OS の画面の字と絵で書く（「共有」「その他」「ホーム画面に追加」「追加」など。自分の画面で同じ字を探せるように）。字はスマホの言葉（`navigator.language`）に合わせ、日本語でなければ英語の字（Share・More・Add to Home Screen・Add）を出す。数字は URAJI
- 一覧はページの上に置く。OS のメニューやシートは下から出て画面の下半分を隠すが、上の一覧は操作の途中も見えたまま
- 最初に押すボタンは、本物のバーと同じ並びの絵（`scenes.ts` の1枚目の場面の、バーの帯だけ）で場所を見せ、本物のボタンを矢印で指す
- 手ごとに一言（右下の •••・見えなければ上へ送る など）を添え、もう一方の言葉（日本語のスマホなら英語）でも「押すものの字 — 場所」を書く（11/6 本人「B かつ英語も入れて」）。題も2つの言葉で出す
- 出ないこともある手は点線（iPhone の Chrome などで、iOS の版が分からないときの「その他」）

| 開いたところ | 手順 |
| --- | --- |
| iPhone の Safari 26 から | 右下の ••• → 共有 → その他 → 「ホーム画面に追加」 → 右上の「追加」 → ホーム画面のアイコン |
| iPhone の Safari 18 まで | 共有（下の真ん中） → 「ホーム画面に追加」 → 「追加」 → アイコン |
| iPhone の Chrome など | 右上の共有 →（iOS 26 から）その他 → 「ホーム画面に追加」 → 「追加」 → アイコン |
| Android | Chrome がボタン1つで入れられるときは、アイコンと ↓ のボタン1つだけ。出せないときは ⋮ → 「アプリをインストール」 → 「インストール」 → アイコン |
| LINE の中 | 自動で `?openExternalBrowser=1` を付けて外のブラウザへ。それでも LINE の中のままなら、右上のメニュー → 「ブラウザで開く」 |
| Instagram などアプリの中 | 右上のメニュー → 「ブラウザで開く」（開き直した先で、その端末の案内が出る） |

- iOS 26 から、共有シートは最初に4つ（コピーなど）だけ見せ、4つ目が「その他」。「ホーム画面に追加」はその先にある（シートを上へ送っても出る）。ソフトバンクの iOS 26 の手順・MacStories の iOS 26 の記事と同じ
- iPhone の手数（Safari 26 で5手）は Apple の画面の中なので、こちらからは減らせない。案内でできるのは見せ方だけ
- Safari 26 の ••• の位置は、本人が選んだタブの並べ方で変わる（標準のまとまった並べ方なら右下。下・上の並べ方なら共有ボタンが直接出る）。案内は標準の並べ方で描いている
- 出さないとき：ホーム画面のアプリから開いたとき・パソコン・試し部屋（`?g=`）・左上の × を押したあと（そのタブの間）
- Safari 26 は UA の OS の版を 18 台に固定しているので、版は `Version/26` で見る
- 見分け方の単体テストは `test/install-detect.test.ts`、手順の一覧は `test/install-steps.test.ts`

アイコンは新字（うらまつり、URAJI v0.3 の案 C）。字の線をアイコンの下から 0.53 の高さに置いた。

- `icon/icon.svg`：iPhone・ふつうの大きさ用（角は iPhone が丸く切る）
- `icon/icon-maskable.svg`：Android 用。丸く切られても欠けないよう、中心から半径 0.4 の円に収めた
- `icon/alt-runner*.svg`：見比べた案（逃走者のピクト）
- PNG の書き出し：`rsvg-convert -w 512 -h 512 icon/icon.svg | convert - -alpha off PNG24:src/client/public/icon-512.png`（192・180・maskable も同じ）
- すでにホーム画面に置いた人のアイコンは替わらない（置いたときの絵のまま）。替えたいときは一度消して置き直してもらう

## 本番の部屋とリハーサル

- ホーム画面に追加したアプリは、いつも部屋 `main` を開く（`manifest.webmanifest` の `start_url` が `/`）。本番も実機テストも `main` で行うのが、本番と同じ流れになる
- 人を集める前に、主催者画面の「新しい夜を始める（名簿は残す）」を押す（前の「部屋を空にする」）。今夜の参加者は全員外れるが名簿は残り、つながっているスマホには名前のボタンが出る。試合中は押せない。誰もいなくても押せる
- 待合室で、前の夜を始めてから12時間より長くたっていたら、主催者画面が「新しい夜を始める」を促す（前の夜のまま集めると、前に来て今夜いない人まで配役に入るため）
- `?g=名前` の部屋は、ブラウザだけで試すとき用（ホーム画面のアプリからは入れない）。名簿も部屋ごと

## 無料枠

Durable Objects の無料プランは1日10万リクエストで、超えるとその日はエラーになる。戻るのは UTC の0時＝日本時間の朝9時なので、昼のリハーサルと夜の本番は同じ枠を使う
（[料金](https://developers.cloudflare.com/durable-objects/platform/pricing/)）。

- スマホから届く WebSocket のメッセージを20通で1リクエストと数える換算は、料金表では有料プランの欄にだけ注記された「課金のための」換算で、**無料プランの上限にも効くかは書かれていない**（2026-11-04 に確認）。サーバーから送る側は無料
- 今届くのは時計合わせだけ（1人あたり30秒ごとに問い合わせ3通＋報告1通）。300人なら毎秒約40通、2時間で約29万通になる。換算が効けば約1.4万リクエストで余裕だが、効かなければ約40分で尽きる
- 試合中の合図（アラーム）は2秒ごとに1リクエスト（1時間に1,800）
- 走ると光るは、光っている1人につき1秒に1通（止まっている人は送らない）。50人のうち平均5人が光るなら、5分のゲーム1回で約1,500
- 全体の地図は、ゲームの段階の間だけ1人5秒に1通。50人なら1分に600、ゲームの段階が1晩で計30分なら約1.8万
- 配役の希望は、板を押した1回につき1通（押した本人にすぐ返し、ほかの人の画面の人数は入室と同じ間隔でまとめて配る）。50人が1ラウンドに2回ずつ押しても100通
- **本番の月だけ有料プラン（最低月5ドル、月100万リクエスト込み）にすれば、どちらの場合でも尽きない**。位置を毎秒送る形にするなら有料プランが前提
